## 기본 실행 흐름

1. `ACTS`에 정의한 동작을 위에서 아래 순서로 실행합니다.
2. `PARAMS` 값을 API 입력으로 전달합니다.
3. 실제 출력값을 `EXPECT`와 비교합니다.
4. 필요한 출력은 `ARTIFACTS`에 지정한 이름으로 저장합니다.
5. 저장한 출력은 이후 동작의 `PARAMS`에서 다시 사용합니다.

## 결과 검증 방식

<ValidationMode title="정확한 값 비교" summary="결과를 미리 알고 있다면 실제 값과 기대값이 같은지 확인합니다.">

```yaml
EXPECT:
  - ret_code: 0
```

</ValidationMode>

<ValidationMode title="조건 기반 검증" summary="정확한 결과를 미리 알 수 없지만 반드시 만족해야 하는 조건이 있을 때 사용합니다.">

```yaml
EXPECT:
  - key_buf: "${{ actual => actual.value !== 0n }}"
```

위 예제는 생성된 key의 정확한 값 대신 전체 값이 `0`이 아닌지 확인합니다.

</ValidationMode>

조건 기반 검증은 buffer 길이, 숫자 범위, byte 값처럼 하나의 고정값으로 표현하기 어려운 요구사항에 적합합니다. 동일한 출력에 정확한 값과 조건 표현식을 함께 작성하면 정확한 값 비교가 우선합니다.

## 출력값 재사용

`ARTIFACTS`는 API 출력을 이후 동작에서 참조할 이름으로 저장합니다.

```yaml
ARTIFACTS:
  fd: secure_file_fd
```

저장한 값은 다음 동작에서 `{{ out.<name> }}` 형식으로 참조합니다.

```yaml
PARAMS:
  fd: "{{ out.secure_file_fd }}"
```

이를 이용하면 파일 열기, 읽기, 쓰기, 닫기처럼 서로 연결된 API 동작을 하나의 Test Case로 구성할 수 있습니다.
